## 本次只测强制重新获取

**不要先清缓存。** 已自行删除的 audio 开头文件属于测试前人工操作，不记产品故障；保留现有视频缓存及观看进度即可。不重做之前已通过的登录态导入、重启认证等全套项目。

让 AI 对已有视频执行：

```json
{"action":"open","source":"原视频地址","refresh":true,"max_height":1080}
```

1. 确认返回 `cache.state: refreshed`，记录实际 `resolution`；1080 是本次上限，不保证源站一定有该质量。默认未传 refresh 的后续 open 仍可命中缓存。
2. 查看全局源视频高度设置没有被这次参数改写，观看进度保留（新视频更短时只截到新末尾）。
3. 确认需要的音频能重新生成/读取，不混用旧派生音轨或旧转写。已删音频的恢复结果单独记录，不要求重新导入登录态。音频分析成功不等于所有语音均已转写。
4. 若自然发生下载失败或主动在采集期间取消，确认原缓存与进度仍在；不必为此制造磁盘故障或删除文件。提交完成后取消不能撤回已完成的替换。

`duration_seconds` 是缓存文件时长；画面 `sampled_range_seconds`、音频 `analyzed_range_seconds` 是本次分析范围。仅分析15秒但文件更长时继续读区间，不必重下；如果文件本身是短片，重新获取后仍看实际时长，不猜原视频完整性。

# 0.10.0-candidate.2：设置页 UI 修订

仅修复以下明确 UI 问题，不引入旧副本迁移或新采集方式：

- 清理按钮简化为“清理登录态”，处理中为“正在清理登录态…”；英文对应简化。确认及结果文字仍准确说明只处理 VV 保存的副本，不清来源/内置浏览器独立登录态或媒体缓存。
- 登录态清理确认放在该按钮所在的浏览器卡片中，不再请求自动滚动。原实现复用了页面下方媒体缓存确认框，`confirm` effect 调用 `scrollIntoView`，首次点击就滚动，尚未发出清理请求。媒体缓存确认仍保留原行为。
- 移除公开界面、错误提示和使用说明中的私有测试工具简称，改为通用的“当前可连接的浏览器来源”。不改发现能力、不隐藏实际来源身份。
- “方法与扩展文件夹”下的说明拆为两行：指导说明一行，“升级插件或清空视频缓存会保留它们。”另一行；英文同步。继承现有皮肤，不添加硬编码配色。

## 验证及范围

新增 `test/browser-clear-scroll.mjs` 覆盖实际 client 代码的 effect/ref 路径：旧代码明确失败（点击后自动滚动一次，清理请求为零）；修复后打开、取消、确认及重新读取均不调用自动滚动，确认位于登录态卡片，媒体确认滚动保留。已有清理成功/部分失败/重试、双语、皮肤及 UI 测试保留。

这是 VM/合成验证，不是用户机器 GUI 验收。独立云 Chromium 保持 sandbox 开启时受环境进程/socket 限制未能启动，未关闭 sandbox 或改安全设置。仍需用户在真实设置页确认：清理前的就地确认、不跳到存储区、取消不清理、指定说明换行与当前皮肤相容。

# 本地任务：旧登录态副本重置、重新导入与传递验证

目标：在用户自己的 DSH Desktop 上整理 Video Vision 的旧登录态副本，重新从用户指定的已登录浏览器导入，记录本次登录态传递结果。由用户将本任务交给其本地执行者；不重复已完成的云端媒体/预算/缓存测试。

## 先区分三个动作

- **“清空全部缓存”**清理视频缓存，不清浏览器登录态，不能用于本任务。
- 关闭 **“授权使用默认浏览器登录态”**会关闭授权与同步、取消进行中的相关请求，但保留加密快照和来源选择。
- 关闭 **“同步至 DSH 内置浏览器”**时，桥会撤回当前进程跟踪的已导入 Cookie，并恢复它覆盖前已有的内置浏览器 Cookie。它不会清空内置浏览器全部 Cookie、localStorage 或其他站点存储；跨进程遗留项也不能仅凭此动作认定已清除。

当前版本没有“清除登录态副本”按钮。不要编造按钮，也不要用关闭授权代替副本重置。

## 执行范围与步骤

1. 核对实际安装候选版本和当前来源浏览器。记录授权/同步开关、导入状态和时间；只记录状态、计数和文件哈希，不输出 Cookie、token、密码或解密内容。源浏览器的登录状态、用户配置、系统密钥必须保留。
2. 先关闭内置同步和登录态授权，等待相关请求结束，再正常退出加载此组件的 DSH Desktop/对应 Host。不得关闭或清理源浏览器。确认组件确已退出，避免内存快照重新写回。
3. 根据**当前实际配置与源码**定位 VV 派生快照，而不是猜用户目录：默认 Desktop 文件名为 `session-state.bin`；CDP 独立来源使用 `cdp/<实际 sourceId>/session-state-keyring.bin`。根位置由 `DSH_BROWSER_SESSION_HOME`、`DSH_HOME` 与运行平台决定。只核本次指定来源，不批量处理其他来源。
4. 如需真正重置旧副本，在用户本机受保护的位置**可恢复地隔离该精确加密快照**，保留原权限和还原路径；不解密、不上传、不删系统密钥、`bridge.key`、来源选择文件 `cdp-selected-source.json`、整个 browser-sessions 目录或原浏览器 profile。不能确认文件归属或服务已退出时，先报告，不继续猜测清理。记录隔离前哈希、原路径是否已不再存在；备份属于敏感登录资料，只保留在本机，不进入报告或 Git。
5. 正常启动同一 DSH 配置。在尚未重新导入时点 **“检查状态”**，记录此来源已无导入快照；核来源选择仍正确。若仍显示已导入，定位实际服务/路径，不把结果强写成功。
6. 保持用户指定的已登录浏览器运行，开启 **“授权使用默认浏览器登录态”**，点 **“导入登录态”**（之后更新用 **“刷新登录态”**）。核新的导入时间、状态及加密快照生成；导入成功会整体替换该来源快照，读取失败会保留原快照，不是追加合并。
7. 用户需要内置浏览器共享时开启 **“同步至 DSH 内置浏览器”**，用正常内置浏览器打开一个用户指定的已登录站点，核页面是否体现目标账号登录；同时用插件实际访问该站点完成最小登录态传递检查。分别记录“获取/保存成功”和“目标站点认可登录态”，不要用公开视频成功代替登录证明。若站点另需 localStorage、设备绑定或再次验证，原样记录实际结果，不扩大清理范围。
8. 结束时按用户期望保存开关状态，报告已做动作、来源浏览器保持登录、重置/重新导入/传递的各自结果。可恢复副本的删除由用户决定；本任务不包含不可恢复删除。

## 源码依据（候选 audit.6）

- `client.js:112–125, 169–190, 239–249`：授权、导入/刷新与媒体缓存按钮。
- `lib/browser-session.js:26–41, 60–76`：授权文件保存、取消请求、导入及来源选择。
- `browser-session/protocol.cjs:6`：实际根目录选择。
- `browser-session/snapshot.cjs:83–98, 113–144`：加密快照文件、内存缓存、成功导入原子替换；读取失败不覆盖。
- `browser-session/cdp-session.cjs:9–12`、`cdp-source.cjs:11`：每个 CDP 来源独立快照、选择信息独立保存。
- `browser-session/sync.cjs:24–36, 45–69`：仅撤回桥跟踪的 Cookie、恢复先前值、访问时同步；不清站点 storage。

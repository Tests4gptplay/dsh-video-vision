# VV host-contract candidate

Source videos are admitted according to the source, decoder and user-selected budgets. No resolution tier or fixed total-duration rule is added. The default six-frame/30-second overview remains an overview, not a capability ceiling.

Frame delivery reads the mounted attachment service imageLimits. A separate compatible copy is produced only when its current per-image byte, pixel, side-length or media-type limits require it; the source frame is retained. Upload-batch counts are not treated as tool-result counts. DSH owns model-route request budgeting and logged offload. Real attachment errors remain errors and do not consume the viewing cursor.

Explicit audio intervals remain complete. DSH mono PCM16 input and the existing recognition windows are retained; only the two identified DSH capacity errors split a rejected window. A stale preparation snapshot does not veto a request the provider may accept. Other errors and cancellation propagate.

User-selected budgets, source access restrictions, browser authorization and encrypted credential scoping remain. yt-dlp and custom resolvers remain anonymous. Cache ownership/mutation locks remain; there is no new handshake, heartbeat or watchdog. Known unedited generated guidance is migrated without deleting appended user notes.

Android issue #2 belongs to DSH attachment-local storage. The accompanying DSH patch/package changes only that owning module. Issue #3 requires the sharp-matched WASM backend to resolve in the same installation as DSH sharp; it is supplied by the accompanying attachment package, not by an unrelated VV dependency.
